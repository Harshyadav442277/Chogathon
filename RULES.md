## Participation and project requirements

1. Solo entries and teams are allowed. The public team interface states a maximum of five members including the lead.
2. Each teammate registers their own profile. The lead links their teammates using X or Discord handles; the team interface also provides invitations that teammates accept through their own sign in.
3. The dashboard specifies one application per person and one project per team. Use My Projects to update the existing entry.
4. Any project category is allowed. AI assisted coding ("vibecoding") is explicitly allowed.
5. The Chog NFT must be central to how the experience works. If removing it leaves the experience effectively unchanged, the entry does not meet the stated requirement.
6. Integrating the $CHOG token is optional. A meaningful integration may receive bonus points; the public rubric does not quantify the bonus.
7. Disclose the repository, tech stack and any work that existed before this hackathon.

Sources: [challenge](https://chogathon.chog.xyz/#challenge), [deliverables](https://chogathon.chog.xyz/#submit), [judging](https://chogathon.chog.xyz/#judging), and the public dashboard's help and team interface text. ## What to submit

| Item | Published expectation |
| :--- | :--- |
| Identity | Project name, team members, Discord and X handles |
| Description | What works, what is new and why Chog NFTs are essential |
| Working demo | A working experience with simple testing instructions |
| Demo video | Up to three minutes, linked from YouTube or Google Drive |
| Technical information | Repository link, tech stack and disclosure of pre-existing work |
| Feedback and next steps | Any real usage or feedback collected, plus what comes next |

The submission interface also provides a banner upload, app URL, contact email, private judge access instructions and an optional go to market plan. The first submission requires a demo video, and a valid contact email is required. Project name and description are required fields. Description, judge instructions and the optional plan each allow up to 8,000 characters.

The form labels repository, contact email and judge access instructions as organizer only. A repository made public on GitHub remains public independently of that form setting. Put credentials only in the private judge access field, never in this repository.

For video access, the site recommends an unlisted YouTube upload or Google Drive sharing set to anyone with the link, Viewer. Check that judges can open the link. Use [docs/SUBMISSION.md](docs/SUBMISSION.md) to prepare the entry and [docs/DEMO.md](docs/DEMO.md) for testing instructions.

Sources: [official deliverables](https://chogathon.chog.xyz/#submit), the [dashboard's How it works panel](https://chogathon.chog.xyz/dashboard), and submission form markup and validation in the official page HTML. These form checks were read without submitting an entry.

## Judging

| Criterion | Weight | What judges assess |
| :--- | ---: | :--- |
| Novelty | 30% | Whether it creates a new way to use or interact with NFTs |
| Fun | 20% | Whether using it is engaging and enjoyable |
| Retention | 20% | Whether people have a reason to return |
| Clarity | 15% | Whether it is understandable and easy to use |
| Execution | 15% | Whether the implementation works well |

NFT essentiality is a requirement in addition to the weighted criteria. Optional $CHOG integration may earn a bonus. The dashboard says judges review descriptions, videos and links after the hackathon ends. See the [official rubric](https://chogathon.chog.xyz/#judging).
